## 二、发现的遗留问题

### 🔴 CRITICAL（必须修复）

#### C1. alerts.case_id 外键约束 → SQLAlchemy 报错
- **位置**: `backend/app/models/alert.py:71`
- **现象**: 数据库外键约束已创建（`fk_alerts_case`），但 SQLAlchemy 运行时仍然报 `NoReferencedTableError`
- **根因**: SQLAlchemy 的 metadata 在进程启动时缓存了表结构，但 `cases` 表可能在 engine 创建后才添加到 metadata。或者 async engine 的外键反射机制有问题
- **影响**: 每次创建/更新 alert 失败，**告警功能完全失效**，消息处理报错
- **修复方案**:
  - 方案A: 从 Alert 模型中移除 `ForeignKey("cases.id")`，改为纯 Integer 列（数据库约束已存在，不需要 SQLAlchemy 知道）
  - 方案B: 在 engine 创建时强制反射所有表（`metadata.reflect(bind=engine)`）
- **风险**: 低
